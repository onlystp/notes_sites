# 預估工時

- 預估工時 303 需要開嗎？
- 寫在 Redmine 的筆記內。預估好之後，通知 PM

# 回報工時

報在議題（甚至可以子任務）：`[開發][空專案] <描述>`


# Slack 功能追蹤

- 可以在追蹤 panel 上 tag 相關的人，在這邊討論功能相關的問題。
- 也可以自己開要追蹤的功能。
- 做完之後用簡單的截圖或簡單的 demo，tag PM 說做好了。 

# Branch Name

- 每個功能一支分支
- `feat/描述/#<issue_num>`

# PR

- 要 demo 給 PM 看過才可以發 PR
	- demo 的時候可以在 VM repo 先 merge 在一起（比方叫做 demo 分支），demo 成功後拆掉，依 feature 分支一個一個發 PR，然後才 tag Reviewer。
- 正式開 PR，並 tag reviewer。
	- 若沒有通過，判斷自己的 PR 需要修的部分還要多久，需不需要先通知 reviewer 。
	- 一來一回確定所有的 resolve 了，這個 PR 才會 merge。
- PR 通過後，PM 或 Reviewer 可能會在 github 開 release flag，將這些 PR 都 merge 進來。
